# Getting help

dynG is pre-alpha and maintained by a small team in its spare research time. Help is given in
public, so that answers are found by the next person with the same question.

| You want to | Go to |
|---|---|
| ask a question, discuss an idea, show what you built | [GitHub Discussions](https://github.com/dyng-dev/dyng/discussions) (categories *Q&A*, *Ideas*, *Show and tell*) |
| report a bug or a wrong result | [a bug report](https://github.com/dyng-dev/dyng/issues/new/choose) (please include the commit, the backend, the compiler and a minimal input) |
| report a slowdown | the *Performance regression* issue form |
| propose a feature or an algorithm | the *Feature request* or *New algorithm* issue form (a Discussion first is welcome) |
| report a security problem | [SECURITY.md](SECURITY.md): privately, **not** in a public issue |
| report a Code of Conduct problem | [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) (e-mail to sm.shovan@gmail.com) |
| contribute | [CONTRIBUTING.md](CONTRIBUTING.md) |

There is **no private e-mail support**: the e-mail address above is only for security and
conduct reports. Please do not ask the same question in several places.

Before asking, please look at [README.md](README.md), the documentation in [docs/](docs/)
(including the algorithm pages under [docs/algorithms/](docs/algorithms/)) and the existing
issues and discussions.

What to expect: questions and issues are usually answered within a week or two. There is no
guaranteed response time, and no commercial support. Bugs that make results wrong are
prioritised over everything else.
