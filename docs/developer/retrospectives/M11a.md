### Deviations from the plan and the step's text (each with the same intent)

1. **Geology (HD15).** The decided recipe, Benson's coauth-MAG-Geology-full re-derived with B's
   and dynG's converters, gives identical bytes on both sides, but not B's measured file:
   1,204,704 lines and 1,261,129 vertices (SHA-256 `e14e2558...`) against `geology.hg`'s
   1,203,895 and 1,256,385 (`884e04ff...`). B's results/README.md names the full archive, but its
   counts are those of the collection's restricted archive (simplices of at most 25 nodes), which
   re-derives `geology.hg` byte for byte with both converters. Both archives are registered; the
   goldens and gates use `geology.hg`, as HD15 directs when the re-derivation differs. Listed for
   the author's acknowledgement (GOVERNANCE.md, "M11 (HD)").
2. **The isolation check of the oracle** lives with its three precedents in `cpp/tests`
   (`check_model_isolation.cmake`, run by ctest, i.e. by `ci/check.sh`'s build step and hosted CI)
   rather than as a new script under `ci/`; the planted violations are two CTests that pass only
   on the check's own failure message.
3. **No struct for the oracle's results**: `std::pair`s of standard containers, so that the oracle
   adds exactly HD12's three names (a result struct would be a new public name for the author).
4. **A vertex source's parent rule.** A hyperedge holding the source vertex and reached from it
   (D(h) == w(h)) has parent -1 even when a lower-id neighbour is also tight: the public-mode
   counterpart of B's virtual source row, which always wins that tie (HD2's documented
   difference). B's own oracle has no vertex source.
5. **The paper cases' loaded rows are stored once per dataset** (`loads/<dataset>.hsd.zst`; B's
   loader is seeded, so a dataset's eight configurations load the same rows), and every paper
   dump holds their digests; the go/no-go splices them back.
6. **The GCC 13 compile** of the new sources was done with GCC 14.3 (conda; the machine has no GCC
   13), with `-D_FORTIFY_SOURCE=3 -O2 -Wall -Wextra -Wpedantic -Werror`, next to the Clang 18
   syntax check of every translation unit and the fortified cpu-only Release build.
7. **The quiet pre-read's probe configuration** is each dataset's heaviest,
   `<dataset>_hyperedge_200000`: if boost holds there it holds on the dataset's lighter cases.
8. **`hyper_sssp.recompute` is emitted on every update** (0 ms without a fallback), so that the
   gated `sosp_update` row is defined on every batch with the existing loader (no optional-stage
   key is added to `REGION_KEYS`).

9. **`certify.py` learns the hyper_sssp golden kind in step 1** (criterion 21 is step 5's):
   adding the set to `parity/goldens.toml` made every certificate test with an unparsable
   version fail (such a certificate needs every set), so the kind's rule (required from 0.4,
   every backend and mode of the set's `[modes]` table, every case; a 0.1-0.3 certificate lists
   it without a verdict) and its test fixture came with the set. Step 5 adds the rest of
   criterion 21 (the suites, the replays of the id records, the dry runs).
10. **`ci/check.sh` ran at the end of the step**, not before every commit: each commit had its
    targeted checks (ruff, the new tests, the oracle builds); the full gate found the
    clang-format layout, one Sphinx warning (a multi-name `@throws`), the certificate tests
    (deviation 9) and a timing-sensitive sampler test, all fixed in the step
    (`31628c8`, `dcef49a`), and passes on the final tree.

### Lessons

- **Export twice, and look at what differs.** The first double export differed in one stderr
  line that held a logged-only counter (the initial recompute's iterations): the same lesson as
  M8a's and M9a's, now caught by the second export rather than by a reviewer.
- **The originals' documentation can name a different input than the one they measured**
  (Geology: the README names the full archive, its counts are the restricted one's); a
  byte-for-byte re-derivation tells which, and both archives are now registered.
- **A shared machine is never quiet**: even inside the exclusive window 1-3 foreign CPU cores ran
  (other users). The probe counts such rounds as not held; the gate readings will retake them.

### Deviations from the plan and the step's text (each with the same intent)

1. **`incidence_delta` runs inside the container's commit** (the stage `hypergraph.apply.translate`
   between `.incidence` and `.line_graph`), not as hyper_sssp's `translate` stage of PLAN 4.5.3's
   sketch: the framework has no translate hook before the commit point, and the container's line
   graph must be exact after every commit with or without an attached algorithm. hyper_sssp reads
   the pairs from the applied record. The region map's `maintain` row (ADR 0080) already counts
   translate inside `hypergraph.apply` (ADR 0086 section 5).
2. **The Python layer refuses** slack_csr storage, `.dgb` files with `incidence_edits` and `.dgt`
   batches with `+i` / `-i` (`NotSupportedError`, "planned for the Python layer of 0.4") until
   M11b, rather than dropping the edits; the generators' Python enum keeps the 0.3 mixes.
3. **No incidence mirror on the host.** B's DeviceIncidence is device-only; its slot rules
   (`he_slot_for`, `v_slot_for`, the re-upload growth) are in `slack_layout.hpp` for step 3's
   CUDA store, and the host store reads its own rows. The host candidate counts equal B's on all
   734 batches; criterion 10 asserts them on the CUDA store only (step 3).
4. **The GCC 13 compile**: a real GCC 13.4 (the conda package cache, as a compile-only front end
   over the system glibc headers) with `-O2 -D_FORTIFY_SOURCE=3 -Werror` over all 569
   translation units of the dev build: 566 compile; 3 test files untouched since the base
   (`graph/allocation_failure_test.cpp`, `io/fuzz_regression_test.cpp`,
   `algorithms/mosp/mosp_allocation_failure_test.cpp`) fail GCC 13's `-Wmismatched-new-delete`
   on their replaced global `operator new` / `delete` under `-O2` (a known false positive of
   that warning), and compile with the dev build's flags. Recorded, not changed in this step.
5. **The DBLP CBST replays** ran without the quadratic `rebuild_line_graph` check (as M8b's DBLP
   line-graph replays); the oracle ran on the same sessions through the P50 dumps.
6. **`dyng-compat-hsosp` writes one `.hg` / `.dgb` / `.txt` per session** (a T dump holds up to 50
   sessions); batches B rejected are not written (counted), and operations a file cannot hold (an
   id below 1, a negative vertex; B skips them) are filtered and counted with the virtual ones.
   Its `replay` checks the ids and skip counts without a line graph (the ids do not depend on it).
7. **`batch_writer::write`** raises `invalid_argument_error` (was `not_supported_error`) for an edit
   in a file opened without the flag: the flags are fixed at open (HD10), so the refusal is the
   caller's argument; an api-change entry.
8. **The allocator keeps the values of a row's tail segment only for rows whose tail is an
   overflow segment** (a single-segment row's tail is the whole row), the smallest state that
   reproduces ESCHER's unfill occupancy.
9. **`ci/check.sh` ran at the end of the step**, as in step 1; every commit had its targeted
   checks.
10. **The step's results are `parity/results/M11a.md` section 8**, not section 2 as the step's
    text says: step 1 numbered its sections 0-7 (section 2 is Geology), so each step appends
    its own section.
11. **The step was resumed after an interruption** (the account's spend limit, about 10:24Z on
    2026-10-29): the commits up to `628e95f` were kept; the resumed session committed the
    uncommitted remainder (the allocation-failure tests of the new regions, the API baseline,
    the records) and ran the step's checks again on the final tree (section 8.7).
12. **tsan-openmp ran through a local wrapper of the conda Clang 18.1.8** (as in R020 and R030:
    `--gcc-install-dir` GCC 12, `--sysroot=/`, `-Wno-deprecated-declarations`, and

### Lessons

- **A shared GPU is shared at every job, not at every step**: a correctness run on GPU 1 is a
  foreign process in the other track's memory reading; ask `quiet-ok` before each one.
- **A model of an unsorted store compares sets.** The first slack replay of the CBST traces
  reported 588 "h2v row differs" against the host model: the model's rows are in slot order after
  fills and unfills, the container's views sorted. The comparator, not the port, was wrong.
- **A sweep of allocation failures must not contain the test's own allocations**: the first slack
  build sweep failed its first allocation in the test's list builder.
- **Order-free by construction is cheaper than order-free by testing**: the pair delta reads only
  the states before and after the batch, so the permutation test and the 1/8-thread replays agree
  by design.
