### Lessons

- **A shared GPU is shared at every job, not at every step**: a correctness run on GPU 1 is a
  foreign process in the other track's memory reading; ask `quiet-ok` before each one.
- **A model of an unsorted store compares sets.** The first slack replay of the CBST traces
  reported 588 "h2v row differs" against the host model: the model's rows are in slot order after
  fills and unfills, the container's views sorted. The comparator, not the port, was wrong.
- **A sweep of allocation failures must not contain the test's own allocations**: the first slack
  build sweep failed its first allocation in the test's list builder.
- **Order-free by construction is cheaper than order-free by testing**: the pair delta reads only
  the states before and after the batch, so the permutation test and the 1/8-thread replays agree
  by design.

### Deviations from the plan and the step's text (each with the same intent)

1. **The host side of a batch was rewritten in this step** (ADR 0089 section 8), not only

### Lessons

- **Profile the host side of a GPU port first.** The transplanted kernels were B's from the first
  commit; the cost was in the host passes around them (copies, sorts, groupings, read-backs, and
  an O(|E|) scan of the allocator per insert), each cheap alone and together 2-6x B's row.
- **More threads are not faster on a shared host.** A 56-thread team lost to a 16-thread one on
  every region measured, the build included; and changing team sizes is not free in libgomp.
- **Group by the key that makes the work independent** (the hyperedge for Step 0, the vertex for
  v2h): the parallel result is the sequential one by construction, and one radix sort replaces
  several comparison sorts.

### Lessons

- **A fake through the framework first is cheap and finds the bend early**: the budget hook was
  the only framework change, found before any engine code depended on the enactor's shape.
- **Transplant, then make the mechanical classes one commit each, replaying after every one**:
  a divergence would have pointed at one class, and the SASS stayed B's except where a hunk
  changed the code on purpose.
- **Digest every call's result and compare digests across runs and backends** (`--repeat`,
  `--same-as`): sequential == cuda and the ten repeated runs became checks of the same record
  format rather than separate harnesses.

## The review of M11a (independent reviewers' confirmed findings)

Twenty-four findings, each confirmed by a skeptic, were fixed on the branch in small commits (base
of the fixes `328d1f2`), with the affected tests, replays and readings taken again on the fixed
code (`parity/results/M11a.md` section 12).

### What was fixed

- **Robustness of the cuda paths.** An empty hypergraph sized a result's device state 0 and left
  a launch error pending that the next commit reported as its own (`f691f9e`); a growth of a
  result's device state cost three host synchronizations against an allowance of two, an
  `internal_error` under strict budgets (`96499f2`); more than INT_MAX real candidates was an
  `out_of_memory_error` instead of the documented `capacity_error` (`57efd95`, with a test of the
  device error words of class c2).
- **Checks that could not fail.** HD8's work and iteration triggers are pinned by tests (a 1.5x
  limit and an off-by-one cap passed before; `9f38dc1`); the public parity modes are checked by
  the oracle itself, by_key resolves by content, an apply_batch without its begin_batch and an
  unchecked call fail, digest mode covers ids past B's bound (`4a0f7ee`, `c0c39e7`); the gate
  harness's round guard requires the result group of a full reading (`d263f6e`), a vanished GPU
  process is foreign unless it was seen as the reading's own (`3f8dc63`), the audit's quiet
  maximum comes from the pre-read record (`71120cf`, `c29978b`); the (0, 4) key is counted in the
  source (`10bdae9`); the SASS identity names and checks its base commit (`14de3cb`).
- **The gate scope.** maintain[bN] missed Step 0 inside `hyper_sssp::update`
  (`hyper_sssp.normalize` runs outside `hypergraph.apply`; `bf6ec64`); Geology is read at base as
  coauth-DBLP is (`ba1120b`); the 16 gated configurations were read again on the fixed code
  (`e7f2da6`: 271 of 271 within their bars; the smallest margin 1.033, dblp_hyperedge_25000's
  first batch).
- **Records and documents.** The store's transplanted kernels have their SASS record
  (`a596103`); the kit's incidence mixes reach the dead-id skip rule (`dabcec8`); the frozen
  headers, the CHANGELOG and the formats page say what 0.4 does (`dc1672e`); the D14 list and the
  memory-row count of the records were corrected.

### Deviations and open items

- **The pause.** The review's work paused at the author's weekly-usage limit while M10a held the
  exclusive lock; still to be taken on the reviewed code (`$DYNG_SCRATCH/runs/m11a-review/
  chain2.sh` runs them in order, each window through `tools/locklog.py`): the default-clock
  reading and the ncu kernel table (EXCL), the gated memory reading (GPU1-QUIET), then
  `bench_suite.py summarize` and the dry 0.4 certify (which refuses the step-5 records of those
  three as not the release's code), ADR 0024's four readings on the final library and the 85 x
  170 reading of syn1M's host delete on openmp-8 (rule 3; listed for the author meanwhile), and the
  final checks of `parity/results/M11a.md` section 11.9.
- **Not located:** the first batch's id stage of dblp_hyperedge_25000 / 100000 / 200000 read 6-9 ms
  more than in step 5 on unchanged allocator code (every gate holds; candidate: a first-touch or
  memory-state effect). M11b reads the suite again and should look at it.

- The maintain rows were not re-derived from the first reading's rounds: the suite was read again
  with the amended map (the library also changed), so every gated number traces to a reading of

### Lessons

- **A trigger test needs a case on each side of the edge.** Budgets of 0 and infinity prove that
  the action runs, not where the limit is.
- **A check that reads the system under test's own state is not an oracle.** The public modes'
  canonical rule ran over the store's host model, which the engine also reads.
- **A stage map must be checked against the path that is timed.** Step 0 was named inside
  `hypergraph.apply` because the maintain-only reading emits it there; the update path emits it
  outside. A planted delay per stage now proves each gated row's scope.
