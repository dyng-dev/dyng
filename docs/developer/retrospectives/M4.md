### Deviations from the plan (pragmatic choices, same intent)

| Plan | What was done | Why |
|---|---|---|
| Section 8.9: "DCO sign-off on every commit" | sign-off required from **external contributors**; members of `dyng-dev` are exempt (`.github/dco.yml`, `require.members: false`) | the M4 brief asks for DCO sign-off for external contributors; the maintainers' commits already carry their identity and a `Co-Authored-By` trailer, and the history has no `Signed-off-by` lines |
| Section 10.2 label `help-wanted` | `help wanted` (GitHub's standard name), and a generic `good first issue` next to the plan's `good-first-issue:<category>` labels | GitHub lists issues with exactly these two names on the repository's `/contribute` page |
| Section 10.1 issue forms | also `performance_regression.yml` and `docs.yml` | the M4 acceptance criteria ask for them |
| no label workflow in Section 8.8 | `.github/workflows/labels.yml` applies `labels.yml` (dry run on pull requests) | otherwise the author would have to create 46 labels by hand; the file stays the single source of truth |
| Section 4.2 lists "three scripts" of tooling | one more checker, `ci/github_meta_check.py`, as a pre-commit hook | GitHub validates issue forms, CODEOWNERS and labels only after a push; a broken form silently falls back to a blank issue |
| Section 8.9 rule 6: the CODEOWNERS algorithm block is generated from the manifests | written by hand, marked as the block `scripts/regen.py` will generate from M3 on | `scripts/regen.py` does not exist yet |
| Section 9.2 (Read the Docs installs the docs requirements) | `.readthedocs.yaml` uses the conda environment `environment.yml` | the M4 brief asks for the same pinned tool versions as `environment.yml`, including Doxygen 1.18.0 |
