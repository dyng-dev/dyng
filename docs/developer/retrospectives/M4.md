  versions), reference (the algorithm catalogue, the curated C++ API with one `doxygengroup`
  page per Doxygen group, the file formats), developer (the plan, contributing, writing
  documentation, the parity guide included from `parity/README.md`, labels, repository
  settings, the name reservation, the retrospectives), the ADRs (`docs/adr/index.md` includes
  the README's table; the ADRs are globbed), roadmap, how to cite (the bibliography rendered
  from `docs/references.bib`, the BibTeX and `CITATION.cff`), changelog (included from
  `CHANGELOG.md`) and a glossary. A landing page with the tagline, the algorithm table (`sssp`
  now, the others marked planned with their release), install and build, a first update, and
  "How to cite". Every existing page (`algorithms/sssp.md`, `api/file_formats.md`, the ADRs,
  the retrospectives, `labels.md`, `repository_settings.md`, `pypi_name_reservation.md`) is
  part of the site.
- **`docs/_ext/dyng_breathe.py`**, a small local extension for three Breathe limitations found
  while making the reference build warning-free: (1) on group pages Breathe declares free
  functions, enumerations and aliases in the global scope (`to_vector`, not
  `dyng::to_vector`), so 134 references did not resolve; the extension qualifies them with
  Doxygen's `<qualifiedname>`; (2) Doxygen links `@ref sssp` and header names to group and
  file pages that a group-based reference does not have; they are resolved to the page that
  renders the group (a header: its `@ingroup` group), and a Doxygen group without a page is a
  warning, so a new group cannot go missing; (3) Doxygen 1.18 emits `constexpr` twice for
  constexpr constructors, which Sphinx cannot parse.
- **`ci/docs.sh`** now builds everything: Doxygen with warnings as errors and
  `ci/doxygen_coverage.py` (unchanged), `sphinx-build -W --keep-going -n -E` into
  `build/docs/html`, and the `linkcheck` builder for internal links (documents, anchors, local
  files; external links only with `DYNG_LINKCHECK_EXTERNAL=1`). `--doxygen-only` keeps the old
  behaviour for `lint.yml`, the CMake target `docs-doxygen` and the Read the Docs pre-build;
  `--no-linkcheck` skips step 3. It removes stale Doxygen XML before each run.
- **`.github/workflows/docs.yml`**: job `site` on pushes to `main`, pull requests and on demand
  (micromamba installs `environment.yml`, so the versions are those of the local environment
  and of `.readthedocs.yaml`; configure-only `cpu-only` preset; `ci/docs.sh`; the site uploaded
  as the artifact `docs-html`); job `external-links` weekly and on demand
  (`DYNG_LINKCHECK_EXTERNAL=1`), not a required check. `permissions: contents: read`,
  `persist-credentials: false`, actions pinned by SHA.
- **`environment.yml`** pins Sphinx 8.2.3, myst-parser 5.1.0, linkify-it-py 2.2.0,
  pydata-sphinx-theme 0.22.0, Breathe 5.0.0, sphinx-copybutton 0.5.2, sphinx-design 0.7.0 and
  sphinxcontrib-bibtex 2.7.0; the `dyng-dev` environment was updated and the conda cache
  cleaned.
- **`docs/developer/plan.md`** (the short roadmap, from PLAN Sections 0, 1, 11, 12 and
  Appendix E, with the M1a re-estimate) and **`docs/roadmap.md`** (the public roadmap, PLAN
  Section 10.5).
- Follow-ups of Step 1: the site-build command in `CONTRIBUTING.md`; the `docs.yml` required
  check (`site`) and the micromamba action in the Actions allow list of
  `docs/developer/repository_settings.md`; `labels.md` and `repository_settings.md` in the
