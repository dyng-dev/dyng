### Lessons

- **Turn each manual validation into a check.** Steps 1 and 2 validated the issue forms, the
  pins and actionlint by hand; the pins and actionlint are now hooks or a script option, so
  they stay true after the next workflow edit. The self-test's rule "every mutation must be
  rejected" also guards the test itself: a mutation that no longer applies (the fixture text
  moved) leaves the input unchanged, is accepted, and fails the self-test.
- **Use two linters for workflows.** actionlint checks syntax, types and shell; zizmor checks
  security properties (credentials, injection, permissions, supply chain). Each found things
  the other does not.
- **Required checks couple to job names.** Renaming a job, or giving it a `name:`, silently
  turns a required check into one that never reports, which blocks every pull request. The
  settings guide lists the exact names; keep it in the same pull request as any rename.
- **Trial-merge a parallel branch early.** Merging `main` into a scratch clone and running the
  full gate costs two minutes and turns "the merge may break the docs build" into evidence.

### Lessons

- **A check that cannot fail is not a check.** The linkcheck step printed "OK" while checking
  nothing; reading the builder's `output.json` counts (all `unchecked` or `ignored`) would have
  shown it. Every new gate step now comes with a negative test.
- **"CI runs the same steps" has to be checked step by step.** A table of ci/check.sh steps
  against workflow jobs (now in the header of `ci/check.sh`) found the missing tidy job.
- **Grep what the newcomer reads, not only the diff.** The machine-specific defaults were in
  files M4 did not change but sent contributors to.
