## Step 3: documentation and close-out

### Done

- **Python API reference** (PLAN 9.2): sphinx-autoapi 3.8.1 reads `python/dyng` and the committed
  stubs statically (no compiled module, so the docs job, Read the Docs and CPU-only machines need
  no build). The reference is the public API as users import it: the `dyng` package page with
  every name of `dyng.__all__`, and one page each for `dyng.sssp`, `dyng.cycle_count`, `dyng.io`,
  `dyng.generators` and `dyng.testing`. The implementation modules whose names the package
  re-exports (`dyng.graph`, `dyng.array`, ...) get no page of their own, and a `missing-reference`
  hook resolves the signatures' `dyng.graph.Graph` to the documented `dyng.Graph`. The docstrings
  needed two fixes for the reference: the `#:` field comments of the dataclasses (which autoapi
  does not read) became "Attributes" sections, and nine property docstrings that started with
  "text: ..." (which napoleon reads as a type) were reworded. `docs/api/python/index.md` explains
  the package-wide rules (resources, dtype dispatch, arrays, stale results, the exception table,
  threads, profiling).
- **Getting started**: the index page shows both ten-line quickstarts (included from the README,
  so they are the tested ones); `install.md` has the Python section; "A first update in Python"
  (`examples/python/first_update.py`, the twin of the C++ page, and a `dyng.update()` snippet with
  sssp and cycle_count on one graph).
- **README quickstarts executed** (PLAN 9.6): marked code blocks (`<!-- snippet: name -->`, an
  optional output block) in the READMEs and the pages. `python/tests/test_doc_snippets.py` runs
  every Python snippet (6 today: the two READMEs, the first update, both algorithm pages) and
  compares its output; the CTest `example.readme_quickstart` extracts the C++ quickstart at
  configure time, compiles it with the examples' warnings and compares its output;
  `ci/doc_snippets.py --check` (in `ci/docs.sh`, tested by `ci/tests/test_doc_snippets.py`) keeps
  the quickstarts present and within ten lines.
- **`examples/python`** (`first_update.py`, `sssp_update.py`, `cycle_count_update.py`, the twins
  of the C++ examples), tested against the originals' outputs by `python/tests/test_examples.py`.
- **Algorithm pages**: a runnable Python snippet with its output and the command lines on the
  originals' formats in the API sections of `sssp` and `cycle_count`; the "Python binding arrives
  in M5" notes are gone. The update-model page shows the profiler stages from Python.
- **How-to "Port research code"** (PLAN 6.3), written from what the sssp and cycle_count ports did,
  with the harness's real commands.
- **History pages** for MOSP-OpenMP, MOSP-CUDA and CycleEnumeration-GPU (PLAN 9.2): provenance,
  the pinned commit and the paper's snapshot, the ported files, the fixes of the original before
  the port, what differs and what stays behind.
- **`api-check.yml`** (a PLAN 11.2 M5 workflow, left open by step 2) with `ci/api_check.sh`:
  griffe 2.3.0 against the base branch; a breaking change needs the `api-change` label and a
  CHANGELOG entry (PLAN 5.9). The `api` step of `ci/check.sh` runs it locally.
- **Release process** (`docs/developer/release.md`, PLAN 10.3), referenced by `wheels.md` and by
  an error message of `release.yml` since step 2.
- **Repository state of 2026-09-30** (`pending_author_facts.md`): the approvals-log row in
  `GOVERNANCE.md` and steps 7 and 9 of `repository_settings.md` (DCO required, 18 checks,
  the signing key; the pyyaml pin of the harness job).
- The roadmap's "Where we are", the landing page and the README say where 0.1.0 stands; the
  CHANGELOG has the draft summary of 0.1.0 at the top of `Unreleased`.

### Deviations from the plan (pragmatic choices, same intent)

| Plan | What was done | Why |
|---|---|---|
| PLAN 9.2: sphinx-autoapi "over the nanobind stubs (.pyi)" | autoapi over the typed layer `python/dyng/*.py` **and** the stubs | the public API is the typed layer (ADR 0011); the stubs describe only the private `dyng._core`. Both are read statically, so the intent (no compilation for the docs) holds |
| PLAN 9.6: the README quickstarts are run "by a CI step (`ci/docs.sh`)" | the Python snippets run in pytest (`python.yml`, `ci/python.sh`), the C++ one in CTest (`cpu.yml`, `ci/check.sh`); `ci/docs.sh` runs the structural check | the docs job configures but builds nothing (Doxygen, Sphinx), and running the snippets needs the compiled library; the jobs that build it run them, so they still cannot drift |
| PLAN 9.6: "10 lines of C++" | ten lines in the body of `main()` (with the two includes and the braces, 15 lines); ten non-blank lines of Python | a complete, compilable program; `ci/doc_snippets.py` counts it this way |
| PLAN 9.2 tutorials "Dynamic SSSP in Python in 10 minutes" and "Cycle counting on a changing graph" (0.1) | moved to 0.1.x; "A first update in Python" and the algorithm pages' Python sections cover the steps | not in the M5 criteria; recorded in `docs/tutorials/index.md` and the roadmap |
| PLAN 10.3 step 7: "GitHub Release from the CHANGELOG section" by `release.yml` | a manual step of the author (`gh release create`), documented in `release.md` | a job with `contents: write` on tags is a publishing change; left to the author with the tag |
| PLAN 5.9: `api-check.yml` checks against "the last tag" | against the pull request's base branch | the only tag, v0.0.1, is the name reservation without an API; against the base branch every pull request is checked from now on. From 0.1.0 a release branch can compare with the tag (`ci/api_check.sh v0.1.0`) |
| PLAN 6.3 step 10: maturity `stable` at the end of a port | `sssp` and `cycle_count` stay `experimental` | step 10 also asks for the benchmark-suite record (`benchmarks/`, PLAN 8.5), which does not exist yet; the change is left for the release decision (readiness item 12) |

### Notes

- `autoapi_keep_files` is off: the generated pages exist only during the build (and are
  git-ignored). The `source-read` hook gives them the Python default domain, because the site's
  primary domain is C++.
- The pure docstring changes of the typed layer changed no signature: `ci/api_check.sh` against
  `1a11913` (the end of step 2) reports no breaking change.
