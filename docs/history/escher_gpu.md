# ESCHER-GPU

ESCHER-GPU is the code of ESCHER and ESCHER+ (IPDPS 2026, TKDE 2026; `dyng.citation("triad_count")`,
keys `escher2026` and `escherplus2026`): a GPU data structure for dynamic hypergraphs built from
Complete Binary Search Trees (CBSTs) for the hyperedge-to-vertex (H2V), vertex-to-hyperedge (V2H)
and hyperedge-to-hyperedge (H2H, the line graph) relations, updated in place under batches of
hyperedge deletions and insertions, and the h-motif triad counts that run on it. dynG's ESCHER
store (`hypergraph_storage::escher`, the `hypergraph` container) and `triad_count` are ports of it.

The code was a CUDA research prototype with a hand-written Makefile, five executables (`main` for
the 30-bin h-motif counts, `type1`-`type3` for StatHyper's triad statistics, `coarseTriangle`) and
one hard-coded batch. Its 2026 fixes (the branch `fix/correctness-perf`) gave it a shared driver,
a dataset loader, multi-batch runs, stage timers, a CPU reference counter, a CBST integrity checker
and `make test`, which dynG's parity harness builds on.

## What was fixed in the original before the port

Recorded in the original's `CHANGES.md` (E-C: correctness, EP: GPU performance, H-E: host
performance), on coauth-DBLP (2,467,389 hyperedges, a line graph of 251.5M entries) and the
synthetic 1M / 2M hypergraphs, against `baseline-2026-09`:

- **E-C1** the CBST position formula overflowed int32 above 65,535 keys, so searches failed and the
  counting kernels skipped almost everything (1,430 triangles on coauth instead of 8,354,454,505);
  **E-C2** a missing row terminator; **E-C4** 32-bit bins that overflowed on coauth.
- **E-C3** the papers' anchored delta was inexact (coauth, 50K batch: delta sum -88,969,857 against
  the true +1,771,385); replaced by the exact frontier-incident delta (EP1), the delta dynG ports.
- **E-C5**, **E-C6**, **E-C9** the best-fit reuse insert truncated rows, V2H used shifted keys and
  stale occupancy, and unfill across chained segments corrupted later fills; **E-C7** the type-2
  and type-3 deltas counted only part of the changed pairs (and the open h-motifs are out of scope
  by design); **E-C8** a time-seeded RNG per call; **E-C10** debug output in the timed path.
- **EP2-EP5, H-E1** the wedge-parallel counting kernels with row views, the GPU sorted delta merge
  of H2H, per-tree payload capacities and device-side tree operations, the parallel host build:
  coauth 50K per batch 136.7 s -> 0.546 s and the full count 78.7 s -> 5.2 s against the
  correctness-equivalent baseline (`results/README.md`).

The wording of the three items the papers' figures depend on (E-C1, E-C3, E-C7) is "Paper vs fixed
code" on the {doc}`../algorithms/triad_count` page.

## What differs in dynG

- **One container, two originals.** ESCHER-GPU's store and MOSP_ESCHER's are merged into one store
  with presets (`capacity_policy::escher_gpu()`, `mosp_escher()`, `dyng_default()`; ADRs 0039,
  0040), and the hypergraph container keeps the store, the line graph and the row views per version
  with fewer host synchronizations (19-22 per batch against ESCHER-GPU's 90-96).
- **Exact on every backend.** The sequential and OpenMP backends run the same engine as loops
  (incremental, not a recount); the counts are exact up to 2^64 - 1 everywhere and refused past it
  (ADR 0057), where ESCHER-GPU's StatHyper arithmetic wraps from 2,097,152 members per hyperedge.
- **The engine is an extension point.** `experimental::count_local_patterns<op_t>` runs a user's
  pattern (an Op) on the same engine with the same exact updates
  ({doc}`../tutorials/count_a_new_hypergraph_pattern`).
- **Ids.** Bins and hyperedge ids are 0-based (ESCHER-GPU's h-motif k is bin k - 1, its CBST key
  k + 1 is hyperedge k); no key, `+1` shift or sentinel appears in the API.

The mapping of every name is section 9 of {doc}`../algorithms/triad_count`.
